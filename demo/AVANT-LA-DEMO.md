# Liste de contrôle avant la démonstration

À cocher la veille, puis une dernière fois 15 minutes avant.

**L'application**
- [ ] La version publiée contient le dossier `demo/` (plans, jeu, PDF). Ouvrir l'adresse d'un plan pour vérifier qu'il s'affiche.
- [ ] Connexion en super administrateur dans le projet TEST (ou le projet prévu pour la démonstration).
- [ ] Le projet est vide de chantiers de démonstration, ou on accepte de les voir déjà là. Dans le doute : « Retirer le jeu de démonstration » puis « Charger ».
- [ ] « Charger le jeu de démonstration » fait : le message dit combien de chantiers, d'ouvrages, de pièces et de plans ont été ajoutés.
- [ ] Les 7 chantiers « Démo · … » apparaissent. Un plan s'ouvre avec ses pièces.
- [ ] L'agent IA répond (fonction serveur déployée). Sinon, préparer l'exemple et le dire d'avance.
- [ ] Le flux devis, pointage, situation, facture est disponible dans la version montrée. Sinon, ne pas promettre : montrer les données neutres et dire ce qui est en construction.

**Les appareils**
- [ ] Téléphone et tablette connectés, même compte, batterie pleine.
- [ ] Une photo de chantier prête dans la galerie du téléphone (pour l'exemple « prendre une photo »).
- [ ] Le téléphone a du réseau dans la salle (sinon partager la connexion).

**Les fichiers à portée de main**
- [ ] `demo/pdf/c1-residence-les-tilleuls.pdf` (lecture de plans par l'agent).
- [ ] `demo/echange/c1-residence-les-tilleuls.json` (import plugin).
- [ ] `demo/neutre/devis-situations-neutres.json` (montrer la logique des devis si le flux n'est pas prêt).

**Le client**
- [ ] Savoir combien de chantiers il suit, ses corps d'état, et s'il émet les situations lui-même.
- [ ] Prévoir sa question « et mes vraies données ? » : le jeu est fictif et se retire en un clic.

**Après la démonstration**
- [ ] « Retirer le jeu de démonstration » si le projet doit être rendu propre.
